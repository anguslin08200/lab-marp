## 範圍

- 這份指引只供 Lab Slides 工作台的 Codex 對話使用，不寫入其他專案或全域設定。
- 報告原則整理自實驗室的 `How to Do Paper Presentation.pdf`（轉換稿：`../templates/reference.md`）。
- 對話中明確指定的時間、用途、語言、頁數優先於本檔。

## 報告時間與頁數

- 未指定時，日常／論文報告約 **30 分鐘**主講，Q&A 另計。
- 頁數依時間、語速、內容密度決定；每頁約 2 分鐘只是起始估算，不是硬性限制。
- 參考：20 分鐘日常報告約 10–13 頁；限時正式會議約 7–10 頁。
- 規劃整份報告時，列出各段／各頁的估計時間並標示為估算；提醒實際彩排計時。
- 只是局部修改或詢問時，不要擅自擴充整份簡報。

## 內容結構

論文報告預設流程：封面 → Outline → Introduction → Preliminary → Method／Architecture → Experimental Results → Discussion → Conclusion → Q&A。各章節前可放 Outline 導覽頁並突出目前章節，續頁可標 `(Cont'd)`。

1. 標題：論文題目、期刊／會議、年份、作者與單位、報告者。
2. 背景與動機：問題、重要性、必要術語、先前研究、研究缺口。
3. 方法：依邏輯解釋為什麼與如何運作；用圖、表、流程輔助，指出貢獻。
4. 實驗：交代足以理解結果的設定，解釋圖表、差異與意義。
5. 討論：重要發現、與先前研究的關係、主要限制。
6. 結論與展望：只根據已呈現的發現。

缺少資料時使用清楚標示的待補欄位，**不可捏造結果、論文事實、文獻或數據**。保留既有來源與圖表路徑；圖表要解釋它表示什麼。

## 排版與表達

- 保留使用者選用的格式；CATLab 的藍色左側、標題帶、校徽、頁碼保持一致。
- 一頁一個主題，標題要有資訊量（避免「Results 1」）。
- 分點：主項藍色實心方塊、次項藍色箭頭，最多兩層；主項約 28 px、次項約 24 px。
- 文字頁約 8–10 行以內；太密就拆頁或把細節放講者備註，不要縮小字體硬塞。
- 不要用圓角框、底色卡片這類裝飾區塊；並排內容用分欄分點或一般表格。
- 論文截圖放在 Markdown 同層的 `assets/`，在頁面角落標註來源（例如 "Gu & Dao, Figure 3"）。
- 講者備註放在 `<!-- ... -->` HTML 註解中，不把逐字稿塞進正文。
- 修改 CSS 時加上用途註解。在工作台內依回覆 schema 回傳完整 Markdown 提案，不執行命令、不直接改檔。

## 完成前檢查

研究問題與貢獻清楚、段落順序合理、圖表有說明且來源保留、文字可讀、沒有虛構事實；估算時間並提醒彩排。
